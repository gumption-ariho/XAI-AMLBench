# XAI-AMLBench: synthetic multi-hop money-laundering transaction graphs

A privacy-preserving, synthetic benchmark dataset for multi-hop money-laundering detection. Generated by
[`aml_synth`](https://github.com/OWNER/xai-amlbench), the data-generation module of XAI-AMLBench, an explainable
open-source benchmark motivated by FinCEN's April 2026 AML/CFT explainability mandate.

**All data is synthetic.** No real customer, account or transaction data was used to create this dataset, and
none is required to use it.

## Dataset summary

A directed, weighted transaction graph (accounts as nodes, transactions as edges) with five embedded
money-laundering typologies (smurfing, scatter-gather layering, cyclic loops, shell-company chains, cross-border
velocity), realistic benign look-alike structures (large merchants, payroll, rotating savings groups, escrow
chains, cash pooling) so the benchmark is not solvable by amount or degree alone, and ground-truth labels for
which accounts and transactions belong to which injected pattern.

## Loading

```python
from datasets import load_dataset
accounts = load_dataset("OWNER/xai-amlbench", data_files="accounts.csv")
transactions = load_dataset("OWNER/xai-amlbench", data_files="transactions.csv")
```
Or generate your own graph, at any size, with the generator itself:
```bash
pip install xai-amlbench
python -m aml_synth.graph_generator --accounts 50000 --to csv,parquet,json,cypher --out data
```

## Schema

**accounts**: `account_id`, `account_type` (individual/business/shell), `country` (ISO-like code; a small
offshore set is used for secrecy-jurisdiction accounts), `opened_ts` (unix seconds), `risk_score` (a weak,
noisy KYC-style prior in 0-1, *not* the label), `is_suspicious` (0/1 label), `typology` (which pattern the
account first joined, or "none").

**transactions**: `tx_id`, `src`, `dst`, `amount` (USD), `currency`, `payment_format`
(wire/ach/card/cash/crypto_ramp), `timestamp` (unix seconds), `cross_border` (0/1), `is_laundering` (0/1 label),
`typology`, `pattern_id` (-1 for ordinary traffic).

## Splits and reproducibility

The generator is fully deterministic given a `seed`; there is no fixed train/test split shipped with the
dataset, since one is meant to be drawn per experiment (see `gnn_aml_core.train.make_splits`, a stratified
60/20/20 split by default). Report results averaged over several seeds -- see the main repository's README for
measured seed-to-seed variance.

## Limitations

Synthetic data simplifies real laundering behaviour, and labels are the ground truth of injected patterns rather
than real SAR-derived labels, which are noisier in practice. The generator was tuned so that simple per-account
models land near published baseline ranges for this task; this is disclosed, not hidden, and is documented in
the main repository's `aml_synth/README.md`.
